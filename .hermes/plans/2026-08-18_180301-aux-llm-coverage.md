## Was eaccode komplett fehlt (Tool-Bereich)

### T1 — Tool-Registry-System (~1500 Hermes-Funktionen)
Hermes hat:
- **`ToolRegistry`** Singleton mit `register(name, toolset, schema, handler, check_fn, requires_env, is_async, description, emoji, max_result_size_chars, dynamic_schema_overrides, override)`
- **Toolset-System** — Tools sind in Toolsets gruppiert (terminal, web, code, etc.)
- **Toolset-Aliases** — alias-resolution
- **`check_fn`** — runtime-availability-check pro Tool
- **`requires_env`** — env-variable-requirements
- **`is_async`** — async-handlers
- **`max_result_size_chars`** — per-tool-output-cap
- **`dynamic_schema_overrides`** — runtime schema mutations
- **`override=True`** — plugin-override-mechanik
- **`plugin_override_policy`** — operator-opt-in für built-in-overrides
- **Generation-counter** — für cache-invalidation bei MCP-refresh

eaccode: Nur eine einfache `Tool` dataclass mit 7 Feldern. Keine Toolsets, kein check_fn, kein override-mechanismus.

### T2 — Tool-Search Subsystem (~30 Hermes-Funktionen)
- **`is_deferrable_tool_name`** — Core vs Plugin/MCP
- **`classify_tools`** — split (visible, deferrable)
- **`estimate_tokens_from_schemas`** — Token-cost-estimation
- **`should_activate`** — wann Tool-Search aktiv wird
- **`build_catalog`** — searchable catalog
- **`search_catalog`** — BM25-search
- **`tool_search`**, **`tool_describe`**, **`tool_call`** — bridge-tools für Model

eaccode: 0. Tools werden alle immer ins model-facing-array gegeben (38 Tools, ~50K tokens).

### T3 — Context-Overflow Defense (~10 Hermes-Funktionen)
- **Layer 1: per-tool-output-cap** (existiert in eaccode: `max_chars`)
- **Layer 2: per-result-persistence** — wenn output > threshold, write to sandbox, replace with preview+path
- **Layer 3: per-turn-aggregate-budget** — wenn alle results zusammen > 200K, spill largest

eaccode: nur Layer 1.

### T4 — Clarify-Tool (1 Hermes-Tool mit ~10 Funktionen)
- Model kann User **fragen** (multiple-choice) statt zu raten
- `clarify_tool(question, choices, multi_select=False)`
- Inline in REPL gerendert
- Verhindert: Model rät, wenn es nicht sicher ist

eaccode: 0.

### T5 — JSON-Schema-Sanitization (~15 Hermes-Funktionen)
- Manche Provider (OpenAI, DeepSeek, Xiaomi) erfordern **bereinigte** JSON-Schemas
- Hermes: `sanitize_tool_schemas(tools)` — strip $ref, collapse nullable unions, strip const, strip pattern/format
- eaccode: **nichts** — könnte Provider-Fehler verursachen

### T6 — Environment-Probe (~15 Hermes-Funktionen)
- `env_probe.py` — Python version, pip module, PEP668 detection
- Output: "Python 3.11.5, pip available, PEP668 active"
- Wird in system-prompt injected als Tool-Guide
- Hilft Model zu wissen was verfügbar ist

eaccode: 0 — Model rät oder macht `python --version` calls

### T7 — Sub-Agent-Live-Transcript (~15 Hermes-Funktionen)
- `delegation_live_log.py` — Live-Transcript für Sub-Agent-Runs
- Live-Update der Sub-Agent-Aktivitäten
- User sieht was Sub-Agent gerade macht

eaccode: 0 — Sub-Agent-Runs sind **invisible** für User.

### T8 — MCP-Description-Scan (~5 Hermes-Funktionen)
- `_scan_mcp_description(server_name, tool_name, description)` — prüft MCP-Tool-Descriptions auf Prompt-Injection
- Wird beim MCP-Connect einmal ausgeführt
- Verhindert: kompromittierter MCP-Server injiziert Instructions in Description

eaccode: 0.

### T9 — Skill-AST-Audit (~20 Hermes-Funktionen)
- `skills_guard.scan_skill(skill_path)` — pre-install-AST-scan
- Erkennt: prompt-injection, exfiltration, eval/exec, network-egress
- `should_allow_install(result, force)` — Auto-Approve/Deny basierend auf Findings
- `scan_skill_cached(skill_path)` — Cache um wiederholte Scans zu vermeiden

eaccode: 0 — Skills werden ohne Audit installiert.

### T10 — Tool-Middlewares (in model_tools.py)
- `tool_request_middleware` — pre-call
- `tool_execution_middleware` — vor execution

## 12-Phasen-Plan für 1:1 Hermes-Coverage

### Phase G.1 — Tool-Registry-System (T1, ~1500 LOC neu)
- `ToolEntry` dataclass mit allen Hermes-Feldern
- `ToolRegistry` Singleton mit `register/unregister/get_definitions/handle_function_call`
- AST-based auto-discovery (`registry.register(...)`-pattern-detection)
- Toolsets + aliases
- `check_fn`, `requires_env`, `is_async`, `max_result_size_chars`
- `dynamic_schema_overrides`
- `override=True` plugin-policy
- Generation-counter
- **Files:** `src/eaccode/tools/registry.py` (NEU, ~1000 LOC)
- **Files:** `src/eaccode/tools/Tool.py` (refactor zu Hermes-compatible, ~200 LOC)
- **Files:** `src/eaccode/agent.py` Erweiterung — use registry

### Phase G.2 — Tool-Search Subsystem (T2, ~800 LOC neu)
- `is_deferrable_tool_name(name)` — Core vs Plugin
- `classify_tools(tool_defs)` — split
- `estimate_tokens_from_schemas(tool_defs)`
- `should_activate(config, deferrable_tokens, context_length)`
- `build_catalog(tool_defs)`, `search_catalog(catalog, query)`
- Bridge-tools: `tool_search`, `tool_describe`, `tool_call`
- Tiered-disclosure (Core immer, MCP/Plugin nur on-demand)
- **Files:** `src/eaccode/tools/tool_search.py` (NEU, ~800 LOC)
- **Files:** `src/eaccode/agent.py` Erweiterung — activate when context_window tight

### Phase G.3 — Context-Overflow Defense (T3, ~300 LOC neu)
- Layer 2: `maybe_persist_tool_result(result, tool_call_id, env)` — wenn > threshold, write to disk, replace with preview
- Layer 3: `enforce_turn_budget(results, max_chars=200_000)` — spill largest
- `STORAGE_DIR` config
- `<persisted-output>`-tag parsing
- **Files:** `src/eaccode/tools/tool_result_storage.py` (NEU, ~300 LOC)

### Phase G.4 — Clarify-Tool (T4, ~250 LOC neu)
