> **Status:** DRAFT — wartet auf User-Freigabe

## Diagnose

eaccode's Aux-LLM (`smart_reviewer`) wird **nur** aufgerufen wenn:
- `run_command` mit Dangerous-Pattern-Match (z.B. `chmod 777`)
- Pattern matched → aux LLM
- KEIN Pattern matched → direkt auto-approve ohne Aux LLM

**Hermes macht es anders:**
- Aux LLM wird für **mutating actions** aufgerufen, **auch ohne Dangerous-Pattern**
- Aux LLM ist ein **3-stufiger Risk-Assesor**: APPROVE/DENY/ESCALATE
- `mv foo.txt bar.txt` (harmlose File-Operation) → Aux LLM APPROVE → auto-approve
- `mv /etc/passwd /tmp/p` (verdächtig) → Aux LLM ESCALATE → User-Prompt
- `rm -rf /` (klar gefährlich) → Aux LLM DENY → blocked (user kann nicht override)

## Hermes _smart_approve (Referenz)

```python
def _smart_approve(command, description) -> str:
    system_prompt = "You are a security reviewer for an AI coding agent."
    user_prompt = f"The following command was flagged as: {description}\n\n<command>\n{sanitized_command}\n</command>\n\nRespond with exactly one word: APPROVE, DENY, or ESCALATE"
    response = call_llm(task="approval", ...)
    answer = response.choices[0].message.content.strip().upper()
    return {"APPROVE": "approve", "DENY": "deny"}.get(answer, "escalate")
```

## 6 Fixes

### Fix G1 Aux-LLM als Gate für alle mutating tools (auch ohne Dangerous-Pattern)

Heute: Aux-LLM nur wenn Pattern matched. Neu: Aux-LLM für **alle mutating tools** in smart-mode, **auch ohne Pattern-Match**. Aux-LLM wird gefragt "ist das hier gefährlich?" Aux LLM antwortet APPROVE/DENY/ESCALATE.

Aber: Aux-LLM-Cost ist hoch. Hermes-Strategie: **bei Dangerous-Pattern: Aux-LLM immer**, **ohne Dangerous-Pattern: Aux-LLM optional basierend auf Tool-Type**.

Mein Vorschlag (Hermes-Style):
- run_command + dangerous_pattern → Aux LLM
- run_command + safe pattern → auto-approve (jetzt)
- alle mutating tools (write_file, patch_file, git_commit, ...) + smart mode → Aux LLM (vorher: skipped)
- browser_* + smart mode → Aux LLM
- memory_* + smart mode → Aux LLM (das ist **mutating**!)
- read-only tools → skip Aux LLM

### Fix G2 Aux-LLM bei trivialen Aktionen

Hermes-Pattern: Aux-LLM bewertet, was der Aux-LLM **selbst** für riskant hält. mv foo.txt bar.txt = APPROVE (harmlos). mv /etc/passwd ... = ESCALATE (verdächtig).

**Konfigurations-Möglichkeit:** User kann in config.yaml permissions.aux_llm einstellen:
- off: Aux-LLM nie (jetzt-Fallback)
- dangerous_only: nur bei Pattern-Match (heutiges Verhalten)
- all_mutating: Aux-LLM bei jeder mutating Action (Hermes-Stil)

**Default:** all_mutating (Hermes-Stil)

### Fix G3 Description in Aux-LLM-Prompt

Aux-LLM bekommt aktuell nur (command, description). Aber description ist leer wenn Aux-LLM ohne Pattern-Match läuft.

Neu: description = f"tool={tool_name}, action={description}" Aux-LLM weiß **was** für eine Aktion das ist.

### Fix G4 Operator-Policy in System-Prompt

Hermes-Verbatim: User kann in config.yaml permissions.aux_policy als zusätzliche Regeln definieren. Die werden im **System-Prompt** (trusted channel) appended, nicht im User-Message.

```yaml
permissions:
  aux_policy: |
    Always DENY anything that touches /home/admin/.
    Always APPROVE anything in /home/user/dev/.
```

### Fix G5 Sanitize Command vor Aux-LLM

Hermes-Verbatim: strip shell comments (das ist der einfachste Prompt-Injection-Vector). Mein eaccode tut das nicht.

```python
def _strip_shell_comments(command):
    # Strip everything after # that's not inside quotes
    ...
```

### Fix G6 Denial-Breaker

Hermes-Verbatim: Wenn Aux-LLM mehrfach DENY zurückgibt für eine Session, wird die nächste Action ohne Aux-LLM hart geblockt (circuit breaker).

```python
CONSECUTIVE_DENIAL_BREAKER = 3  # 3 DENYs in a row → blocked for session
```

### Fix G7 Owner-Override UX-Patch

palette._ask_owner_override ist definiert aber unused (Sub-Agent Bug 4). Wire es: wenn Aux-LLM owner_override returnt, gehe zu _ask_owner_override (User bekommt only once/deny).
