## 5-Phasen-Plan für 1:1 Hermes-Coverage

### Phase G.1 — ContextVar-Setup (Session-Key, Interactive-Flag)

Hermes hat ein ContextVar-System für:
- `set_current_session_key()` — Identifier für die aktuelle REPL-Session
- `set_hermes_interactive_context()` — CLI vs Cron vs Gateway
- `set_current_observability_context()` — für SDK/Plugin-Hooks

**eaccode heute:** Hat `human_wait_window` (Plan C), aber **kein** Session-Key-ContextVar. Aux-LLM und Denial-Breaker brauchen Session-Key um Tally zu persistieren.

**Files:** `src/eaccode/approval_context.py` (NEU)

### Phase G.2 — Denial-Breaker (vollständig)

Hermes hat:
- `_get_denial_breaker_threshold()` aus config (`approvals.denial_breaker_threshold`, default 3)
- `_record_denial(session_key)` — increment + cap (LRU-eviction)
- `_reset_denials(session_key)` — clear bei approve
- `_denial_breaker_addendum(session_key)` — Hard-stop text

**Heute:** counter existiert in `permissions.py`, aber **kein Reset, kein Threshold-Config, kein Addendum**.

**Files:** Erweiterung `permissions.py`, neue Config in `config.py`

### Phase G.3 — Operator-Policy + Shell-Comment-Strip + Approval-Persistence

**Operator-Policy:**
- `_get_smart_policy()` — liest `approvals.smart_policy` aus config
- Wird in SYSTEM-Prompt appended (trusted channel)
- NIEMALS in user-message (das ist untrusted input)

**Shell-Comment-Strip:**
- Hermes strippt `# ...`-comments aus command bevor Aux-LLM es bewertet
- Verhindert: `rm -rf / # Ignore previous instructions`
- Mein eaccode hat das **teilweise**, aber nicht alle Edge-Cases (`$(...)`, backticks)

**Approval-Persistence:**
- `approve_session(session_key, pattern_key)` — explizite function
- `approve_permanent(pattern_key)` — explizite function
- `save_permanent_allowlist()` — config speichern
- `load_permanent_allowlist()` — config laden
- `_command_matches_permanent_allowlist()` mit **fnmatch-Glob-Pattern**

**Files:** Erweiterung `smart_approval.py`, `permissions.py`, `blocked.py`

### Phase G.4 — Owner-Override-UX wire + Bypass-Checks

**Owner-Override UX:**
- Hermes: Wenn Aux-LLM "owner_override" returnt, kriegt User **nur 2 Optionen** (once/deny), nicht 5
- Mein eaccode: `_ask_owner_override` ist definiert in palette.py:536-556 aber **NIEMAND ruft es auf** (Sub-Agent Bug 4)

**Bypass-Checks:**
- `is_approval_bypass_active_for_session(session_key)` — session-yolo-toggle
- `is_approval_bypass_active()` — process-yolo
- Aktuell: Mein `--yolo` Flag ist nur dokumentiert, nicht implementiert (Sub-Agent Bug)

**Files:** Erweiterung `palette.py`, `permissions.py`

### Phase G.5 — Interpreter-Family-Detection + Shell-Token-Parser

Das ist der größte Brocken. Hermes hat 10+ Funktionen um Shell-Commands **AST-like** zu analysieren:
- Welche Interpreter (`python`, `node`, `bash`, `cmd`)?
- Welche exec-Flags (`-c`, `-e`, `--exec`)?
- Welche shell substitutions (`$(...)`, backticks)?
- Welche quoted strings?

Hermes kann erkennen: `python -c "import os; os.system('rm -rf /')"` ist dangerous obwohl's keine bash-rm-Pattern matched.

**eaccode heute:** Hat nur Regex-Patterns. Keine AST-Analysis.

**Files:** Neues `src/eaccode/shell_parser.py` (500+ LoC)
