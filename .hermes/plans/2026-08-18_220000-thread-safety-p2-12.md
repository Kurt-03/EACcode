# Plan J: Thread-Safety P2.12 — Hermes-Verbatim Analog

> **Vorbau:** Plan I P2.12 hat nur `update_session_cwd` mit Lock abgesichert. Modul-globaler State in `permissions.py`, `todo.py`, `undo.py`, `workspace.py` ist NICHT thread-safe.
> **Hermes-Pattern:** `dict[session_key, value]` + `threading.Lock` für alle reads/writes.

## Audit: Was ist NICHT thread-safe?

| Modul | Globals | Risk |
|---|---|---|
| `permissions.py` | `_MODE_ALIASES`, `_READ_ONLY_TOOL_NAMES` (constant after import, OK), `_session_allowed`, `_ask_handler` | HIGH — `_session_allowed` und `_ask_handler` werden im loop mutiert |
| `workspace.py` | `_active_workspace`, `_session_cwd` | HIGH — schon Lock auf `update_session_cwd`, aber `get_active_workspace()` selbst nicht |
| `todo.py` | `_active_session` | HIGH — keine Lock |
| `undo.py` | `_WRITE_LOCK` | LOW — schon Lock auf write, aber `list_snapshots` ohne Lock |
| `agent.py` | `_loop_permission_checked` (threading.local) | OK |

## Hermes-Pattern (referenz)

Hermes nutzt `session_key` als Param für jeden State-Access:
```python
_session_cwd: dict[str, str] = {}
_session_cwd_lock = threading.RLock()

def get_session_cwd(session_key: Optional[str]) -> Optional[str]:
    key = str(session_key or "default")
    with _session_cwd_lock:
        return _session_cwd.get(key)

def record_session_cwd(session_key: Optional[str], cwd: Optional[str]) -> None:
    key = str(session_key or "default")
    with _session_cwd_lock:
        _session_cwd[key] = cwd
```

## Was ich **nicht** mache (und warum)

- **Komplette Memory/Profile-Migration auf Per-Session**: out-of-scope. Profile-Daten (`memory`, `skills`) sind cross-session by design (Hermes-pattern).
- **Globale `permission_handler` in tools.py**: ist `threading.local`-aware schon (per-thread), kein Lock nötig.
- **`tool_result_storage`**: ist read-only für metrics, keine Race.
- **`mcp.py`**: MCP-Client ist subprocess-based, nicht thread-safe per MCP — Hermes-pattern.

## Risiken

- **API-Bruch**: `Agent.run()` ändert signature. Alle bestehenden Tests müssen angepasst werden.
- **Backward-compat**: Default `session_key="default"` für Tests + einzelne Aufrufe.

## Empfehlung

**Mach J.1 bis J.8 am Stück.** Das ist **riskant** weil viel Code-Pfad berührt ist, aber die Alternative (modul-globals bleiben) ist schlimmer. Wir haben schon einen Lock-Bug der für Tests gemockt wurde — bei echten parallel tool calls wird das in Produktion crashen.
